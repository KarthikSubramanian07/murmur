Closes #399

## Why

`mur join --leave` leaves one repo. It doesn't remove the per-user server entry, hooks or skills, because one entry serves every repo the user joined and a leave can't tell whether its repo was the last (VISION, "Joining a repo"). Nothing else removed them, so taking Murmur off a machine meant following a leave's list of steps by hand, agent by agent. Uninstall can tell: it reads the record of this machine's clones (`internal/clones`).

## Change

- **`mur uninstall [--leave]`** (`internal/join/uninstall.go`, `cmd/mur/main.go`).
  - **Joined clones first.** If a clone on the record is still joined, it refuses and names each one. With `--leave` it leaves each first, and stops if a leave didn't take the consent away.
  - **Every agent configuration join registers in**, T3's instances included, through a new `unregister` per agent next to `register`:
    - Claude Code: the server (through `claude mcp remove` where the command exists, else a text edit), the `mcp__murmur` allow rule, and a notice hook in its own `settings.json` if one was copied there.
    - Codex: the `[mcp_servers.murmur]` table (subtables too), its hook groups in `hooks.json`, and their `[hooks.state.'…']` trust entries (#225). Codex keys trust by a group's place, so the user's own groups after Murmur's move up one. Their trust tables are renamed to the new places so Codex doesn't ask about them again. Both spellings of a home's key are handled (`sameCodexKey`).
    - OpenCode: the server and rule of both shapes (#388/#396), in both `opencode.json` and `.jsonc`.
    - Grok: the server, the `MCPTool(murmur__*)` rule and `hooks/murmur.json`. Muse: the server. Pi: the extension.
    - The skills in every agent that has them.
  - **Join's file rules.** Reads go through `jsonedit.ReadText`: regular files only, under the 256 MiB cap. JSON is re-parsed before it is written. Writes go through `writeAtomic`, which, as join does, writes through a link to its target and keeps the link. A file Murmur owns whole (Grok's hook, Pi's extension, a SKILL.md) is deleted only if it is a regular file with Murmur's marker; a link or someone else's file is left, with a note. A TOML form join wouldn't edit (a dotted key, an inline table) is refused, not guessed at. The user's other entries stay byte for byte.
  - **Daemons.** Those still running for clones on the record are stopped through `client.Stop`. A pre-0.3 daemon can't be asked (#389, #394), and the error names its PID and the command that ends it.
  - **The record.** The record of clones is deleted last.
  - **Left alone, and printed under "Left for you".** Each repo's committed AGENTS.md/CLAUDE.md section, each clone's `.git/murmur` and `refs/murmur/*` (with the command that removes the refs), and the binary. Windows can't delete a running exe, so it prints `Remove-Item`/`rm` for after it exits. It also says the PATH folder stays, because `~/.local/bin` is shared.
- **Leave's advice** now points to `mur uninstall` before the steps by hand. `Report` has a `Left` section.
- **Docs:** the usage text, the README's command table, `docs/agents/join.md`, and a VISION paragraph on why uninstall exists and how it differs from a leave.
