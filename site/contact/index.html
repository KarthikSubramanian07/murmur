Bugs, features and questions

Open an issue at github.com/a-Fig/murmur/issues. For a bug, say what you ran, what you expected and what happened, and include your OS and the output of mur version.

Issues are public, so leave out anything private from your own repo.

Code changes

Pull requests are welcome. Each one closes an issue, so find or open the issue first, and say in the pull request why the change is needed. docs/testing.md says how a change is tested, and the design doc gives the reasons behind the design.

A security problem

Murmur has no private channel for security reports yet. Open an issue that says you found a security problem and which part of Murmur it affects, and leave out the details that would let someone use it. Then ask the maintainer for a private way to send the rest.
