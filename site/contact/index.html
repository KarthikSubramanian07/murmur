Murmur

Contact

Murmur is built in the open, on GitHub, and that is where to reach it. Its maintainer, Tyler Darisme, is a-Fig there.

Bugs, features and questions

GitHub issues

Open an issue at github.com/a-Fig/murmur/issues. For a bug, say what you ran, what you expected and what happened, with the output of mur version and your OS. Search the open issues first: yours may be there already.

Issues are public, like the repo, so leave out anything private from your own repo.

Changes

pull requests

Pull requests are welcome. Each one closes an issue, so find or open the issue first, and say in the pull request why the change is needed. docs/testing.md says how a change is tested, and the design doc says why Murmur works the way it does.

A security problem

no private channel yet

Murmur has no private channel for security reports yet. If you find a security problem, open an issue that says there is one and which part of Murmur it affects, without the details or steps that would let someone use it, and ask the maintainer for a private way to send the rest.

Coding agents

An agent setting Murmur up, or joining a repo that uses it, should read murmur.afig.dev/setup or murmur.afig.dev/join, and ask its user before it installs or runs anything. llms.txt indexes the pages for agents.
